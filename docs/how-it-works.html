Three ways in

The same library reaches people three ways.

A card in the post

  • A microSD card and adapter, sent to a vetted applicant
  • Tap START-HERE and the library opens
  • Watch, read and save — nothing to install

Needs: a phone with a card slot or reader

The village Wi-Fi

  • A Raspberry Pi — or any laptop — serves the card
  • Everyone who joins gets the whole library
  • Phones can send files to each other, still offline

Needs: power and a Pi · no internet

The web link

  • Everything streams from the Digital Bible Society
  • Put it on the home screen like an app
  • Save and send phone to phone from the page

Needs: an internet connection

How phone-to-phone works

The file goes straight across.

The file never touches a server.It travels directly from one phone to the other.

An introducer only swaps the handshake.A few hundred bytes so the phones can find each other — like meeting through a friend, then talking face to face.

A six-digit code pairs them.One phone shows it, the other person types it in.

Who does the introducing

Where you open the library decides who introduces the phones.

On the village Wi-Fi

The Pi does it itself. The server that holds the card passes the handshake between the two phones. Nothing leaves the building.

No internet

On the web link

PeerJS, a free public service. It sees that two phones paired — never what they sent.

Needs internet

Straight off a card

Nothing can introduce them. The app says so, and walks through AirDrop, Quick Share, a cable or the card itself instead.

Guides instead

The chain

Every receiver becomes a sender.

“Send it to someone else” is on every received file.What just arrived becomes the next thing that phone sends — one tap, no searching for it.

Tested over two hops.A 10,024,538-byte Bible went A → B → C and arrived identical, byte for byte. It is VillageServer's rule — let them do the next one while you watch — built into a button.

Before it goes to the field

What still needs doing.

Try it on two real phones.Every test so far ran in a desktop browser standing in for phones.

Urdu and Sindhi need a native speaker.The wording is a draft, and some new screens still fall back to English.

Same Wi-Fi works; different mobile networks may not.Pairing phones on separate carriers needs a relay server.

Android opens PDFs outside the page.A built-in reader (about 1 MB) would keep reading in the app.

Confirm rights with each publisher.Free to receive is not the same as licensed to copy onto cards.

The web broker is free, with no uptime promise.The village Wi-Fi does not depend on it.

The card, the Wi-Fi and the web link are one app. Build it once — it reaches people three ways, and every person it reaches can pass it on.
